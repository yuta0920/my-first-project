# 5090 PC への指示書: 3090 判定ノードに接続する

この PC（5090）の autopilot が使う判定 LLM を、LAN 上の 3090 PC の ollama に切り替える。
5090 の VRAM を H3 生成に専念させるのが目的。以下を上から順に実行し、止まった箇所の「対処」を行う。

## 前提

- 3090 PC では `scripts/setup-3090-ollama-node.ps1` が実行済みで、`ollama serve` が `OLLAMA_HOST=0.0.0.0` で動いている。
- 3090 PC の IP は `<3090_IP>`（3090 側スクリプトの最後に表示される。不明なら手順 1 で探す）。
- 判定に使うモデルは次の 4 本。

| モデル | 用途 |
| --- | --- |
| qwen3-vl:32b | 同一人物・肌の採点 |
| qwen3:32b | 演出指示・翻訳 |
| qwen2.5vl:7b | 絵コンテ適合 |
| deepseek-r1:32b | 予備 |

## 手順 1: 3090 の IP を確かめる

3090 PC で `ipconfig` を実行し、`192.168.` か `10.` で始まる IPv4 アドレスを控える。
5090 PC から届くか確認する。

```powershell
Test-NetConnection <3090_IP> -Port 11434
```

`TcpTestSucceeded : True` なら手順 2 へ。

**False のときの対処（3090 側で行う）**

1. `ollama serve` が動いているか: `Get-Process ollama*`。無ければ `ollama serve` を起動。
2. LAN に公開されているか: `netstat -an | findstr 11434` で `0.0.0.0:11434` が出るか。`127.0.0.1:11434` しか無ければ `OLLAMA_HOST` が効いていない。管理者 PowerShell で下を実行して ollama を再起動する。
   ```powershell
   [Environment]::SetEnvironmentVariable('OLLAMA_HOST','0.0.0.0','User')
   Get-Process ollama* | Stop-Process -Force
   $env:OLLAMA_HOST='0.0.0.0'; Start-Process ollama -ArgumentList 'serve' -WindowStyle Hidden
   ```
3. ファイアウォール: `Get-NetFirewallRule -DisplayName 'Ollama 11434'` が無ければ管理者 PowerShell で作る。
   ```powershell
   New-NetFirewallRule -DisplayName 'Ollama 11434' -Direction Inbound -Protocol TCP -LocalPort 11434 -RemoteAddress LocalSubnet -Action Allow -Profile Any
   ```
4. 両 PC が同じルーター配下か。Wi-Fi と有線で別セグメントになっていないか確認する。

## 手順 2: モデルが揃っているか確かめる

```powershell
(Invoke-RestMethod http://<3090_IP>:11434/api/tags).models.name
```

4 本すべて出れば手順 3 へ。足りなければ 3090 側で `ollama pull <モデル名>` を実行する（32B は 1 本 20GB 前後）。

## 手順 3: JINX_OLLAMA を設定する

```powershell
[Environment]::SetEnvironmentVariable('JINX_OLLAMA', 'http://<3090_IP>:11434', 'User')
$env:JINX_OLLAMA = 'http://<3090_IP>:11434'
```

autopilot を起動しているターミナルは開き直す。ユーザー環境変数は新しいプロセスにしか反映されない。

## 手順 4: 疎通テスト

```powershell
$body = @{ model='qwen2.5vl:7b'; prompt='Reply with the single word OK.'; stream=$false } | ConvertTo-Json
(Invoke-RestMethod "http://<3090_IP>:11434/api/generate" -Method Post -ContentType 'application/json' -Body $body -TimeoutSec 180).response
```

`OK` 相当の応答が返れば完了。autopilot を再起動し、判定ログの接続先が `<3090_IP>` になっていることを確認する。

**遅い、またはタイムアウトするときの対処**

- 初回はモデル読み込みで 10〜30 秒、32B モデルは 1 分程度かかる。`-TimeoutSec` を延ばして再試行する。
- 32B モデルを切り替えるたびに読み込みが走る。3090 は 24GB なので 32B は 1 本ずつしか載らない。判定の順序を同じモデルでまとめると速い。
- `OLLAMA_KEEP_ALIVE=30m` が 3090 側に設定されていないと 5 分でモデルが降ろされる。3090 側で `[Environment]::GetEnvironmentVariable('OLLAMA_KEEP_ALIVE','User')` を確認する。

## 手順 5: どうしても 3090 につながらないときの退避策

5090 単体で判定を回す。生成と VRAM を取り合うので速度は落ちるが止まらない。

```powershell
ollama pull qwen2.5vl:7b
ollama pull qwen3:8b
[Environment]::SetEnvironmentVariable('JINX_OLLAMA', 'http://127.0.0.1:11434', 'User')
$env:JINX_OLLAMA = 'http://127.0.0.1:11434'
```

32B の判定モデルは 5090 で H3 生成と同時には載らないため、退避時は 7B / 8B に落とす。
autopilot 側でモデル名を指定している箇所があれば、`qwen3-vl:32b` を `qwen2.5vl:7b` に、`qwen3:32b` を `qwen3:8b` に読み替える。
3090 が復旧したら手順 3 に戻して `JINX_OLLAMA` を 3090 の IP に戻す。

## 完了報告に含めること

- 使った `JINX_OLLAMA` の値
- 手順 2 で見えたモデル一覧
- 手順 4 の応答と所要秒数
- 退避策を使った場合はその旨と、読み替えたモデル名
